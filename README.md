# Tarot

An interactive tarot card-selection plugin for ChatGPT. Choose a 1-, 2-, 3-, or 7-card Horseshoe spread, pick face-down cards, optionally include reversals, and send the completed spread to the conversation for interpretation.

The service makes no OpenAI API calls and requires no OpenAI API key. It returns cards and reference meanings; ChatGPT handles the conversation using the user's own account.

## Run locally

Requires Node.js 24 and npm. The committed lockfile pins dependencies.

```bash
npm ci
cp .env.example .env
npm run dev
```

Open <http://localhost:8787/preview> for the standalone development UI. The MCP endpoint is <http://localhost:8787/mcp>. The preview provides a copyable spread; it cannot generate a ChatGPT response itself.

The start command loads `.env` when present. Existing operating-system environment values take precedence. Rebuild after widget changes:

```bash
npm run build
npm start
```

## Connect to ChatGPT

1. Run the service and expose `/mcp` through a supported development tunnel or stable HTTPS deployment.
2. Set `PUBLIC_ORIGIN` to that endpoint's origin, with no trailing slash. Restart the server.
3. In ChatGPT Plugins, add a custom MCP server with the HTTPS `/mcp` URL. This MVP has no external user accounts; select no authentication for this anonymous card-selection service.
4. Install the personal plugin and ask it to open an interactive tarot reading. Select your cards, then press **Read my cards**.
5. Verify the returned card names, positions, and orientations against the widget before relying on the live integration.

The widget uses the standard MCP Apps bridge. Session capabilities stay in UI-only metadata and tab-scoped session storage. Completed card data is included directly in the follow-up message, so the handoff does not depend solely on an optional model-context update. If the host rejects the message, copy the provided spread into the conversation.

Reload recovery uses the widget instance identifier from the original tool result, or ChatGPT's optional widget state. Storage-disabled hosts can continue an active reading but cannot guarantee reload recovery. Separate widget instances have separate reading pointers.

## Behavior

- Full 78-card deck with English and Thai names and controls.
- Secure Fisher–Yates shuffle on the server; face-down slot mapping and orientations remain fixed.
- Sequential spread positions, paginated selection, and automatic drawing of the remaining cards.
- Revealed selections cannot be replaced. Starting fresh requires explicit confirmation.
- Atomic revision checks, duplicate-request protection, short-lived sessions, and capability-based access isolation.
- Keyboard controls, reduced-motion support, explicit orientation labels, and responsive layouts.
- Original geometric SVG artwork generated by the widget. It is not a reproduction of a traditional illustrated deck. Reference meanings are original, concise reflection prompts; the detailed reference panel is currently English, while ChatGPT is instructed to interpret in the selected language.

## Checks

```bash
npm run check
npx playwright install --with-deps chromium
npm run test:e2e
```

`check` runs TypeScript validation, domain/service/MCP/HTTP tests, and a production build. Playwright covers desktop and mobile selection, all spreads, paging/reload recovery, a lost response, Thai keyboard controls, and a simulated MCP Apps host receiving an actual `ui/message`. It does not automate a signed-in ChatGPT session.

To run against an existing Chromium executable, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` when running Playwright.

## Shared storage and production

Memory storage is bounded and intended only for local development. Production refuses to start without Redis, HTTPS `PUBLIC_ORIGIN`, and preview disabled.

```env
NODE_ENV=production
HOST=0.0.0.0
STORE=redis
REDIS_URL=redis://your-private-redis:6379
PUBLIC_ORIGIN=https://your-plugin.example
ENABLE_PREVIEW=false
```

Terminate TLS at your hosting ingress. Keep Redis private and use authenticated/TLS Redis URLs when your provider requires them. Sessions expire after two hours of inactivity, never later than 24 hours after creation; both limits are configurable. No question or chat transcript is stored.

The built-in limits are per server process and connection IP: 300 tool requests and 20 new readings per minute. Behind a reverse proxy they apply to the proxy's address because forwarded headers are deliberately not trusted. Add a shared ingress rate limit appropriate to your deployment; do not enable blind forwarding-header trust. Infrastructure traffic, hosting, and Redis remain the operator's responsibility.

## Public release status

This repository is an implementation MVP, not a published directory plugin. Public release still needs a production deployment, real ChatGPT-host verification, developer/domain verification, listing assets, published support/privacy/terms pages, submission materials, and OpenAI review. Do not treat the documentation drafts or automated host simulation as approval. See the [official submission guide](https://developers.openai.com/plugins/deploy/submission).
